# MySQL 锁机制高频面试题（Java 后端，InnoDB 为主，带标准答案）
重点：InnoDB 锁是**基于索引**，RR 隔离级别锁行为变化很大，面试最爱挖间隙锁、临键锁、意向锁、死锁

## 1. MySQL 锁的分类维度（开篇必问）
### 问题：MySQL 锁有哪些分类？
**答案**

1. 按粒度划分：**表级锁、行级锁、页锁（BDB 引擎，基本不用）**
+ MyISAM：只支持**表级锁**，读写互斥，并发差
+ InnoDB：支持**行级锁 + 表级锁（意向锁）**，并发好
2. 按共享排他：**共享锁 S 锁、排他锁 X 锁**
3. 按锁算法（InnoDB RR 特有）：记录锁、间隙锁、临键锁
4. 按实现：乐观锁、悲观锁

一句话区分：悲观锁认为一定会冲突，提前上锁；乐观锁认为冲突少，不加锁，版本号校验。

## 2. 共享锁 S、排他锁 X 锁，兼容性？
**问题：共享锁 S、排他锁 X 是什么，锁兼容矩阵？****答案**

+ **S 共享锁（读锁）**：多个事务可以同时加 S 锁；只读，不能修改。`select ... lock in share mode;`
+ **X 排他锁（写锁）**：只有一个事务持有 X 锁；读写都阻塞。`select ... for update; update / delete / insert` 自动加 X 锁

兼容表：

+ S+S ✅ 兼容（都读）
+ S+X ❌ 互斥
+ X+S ❌ 互斥
+ X+X ❌ 互斥

考点：普通 select 快照读不加锁，走 MVCC；`lock in share mode / for update` 属于**当前读**，加锁。

## 3. 意向锁是什么？IS、IX 意向共享 / 排他锁，作用？（高频）
**问题：意向锁是什么，有什么用？为什么是表级锁？****答案** 意向锁是**InnoDB 表级锁**，不是真正锁数据，是标记：**这个表里面某一行已经加了行锁**。

+ IS：意向共享锁，事务要给表中某行加 S 锁，先给表加 IS
+ IX：意向排他锁，事务要给表中某行加 X 锁，先给表加 IX

兼容性：IS 和 IX 互相兼容；IS/IX 和表级 S/X 锁互斥。

**作用** 如果没有意向锁，当事务想加**全表表锁**时，需要遍历表中每一行判断有没有行锁，代价巨大。 有了意向锁：只需要判断表上意向锁，就能快速判断能不能加表锁，**避免全表扫描检查行锁**。

重点：意向锁之间互不阻塞；意向锁不会阻塞行锁。

## 4. InnoDB 行锁：记录锁 Record Lock
**问题：什么是记录锁？****答案** 记录锁，锁定**索引上的某一条记录**，锁的是索引，不是数据行。 ⚠️ 核心坑：**如果没有索引，行锁会降级成表锁！** 场景：`where id = 1` id 是主键，命中一条记录，加 Record Lock。 RC 隔离级别下只有记录锁。

## 5. 间隙锁 Gap Lock（RR 独有，面试重中之重）
**问题：什么是间隙锁？解决什么问题？RC 为什么没有间隙锁？****答案** 间隙锁，锁住索引记录**之间的间隙**，不锁记录本身，**防止其他事务在间隙插入数据，解决幻读**。 仅存在于 **RR（可重复读）隔离级别**。RC 隔离级别关闭间隙锁。

举例：索引数据 1,5,10 间隙：(-∞,1), (1,5), (5,10), (10,+∞) 事务锁住间隙 (1,5)，别的事务不能在这个区间插入新记录。

注意：间隙锁之间互相兼容！多个事务可以锁住同一个间隙；间隙锁只阻止插入，不阻止修改间隙内已有数据。

## 6. 临键锁 Next-Key Lock（RR 默认锁算法，必考）
**问题：临键锁是什么？****答案** 临键锁 = **记录锁 + 间隙锁**，InnoDB RR 隔离级别**默认行锁算法**，左开右闭区间。 索引：1，5，10 next-key lock for 5：区间 (1,5]，锁住 5 这条记录，同时锁住 1 到 5 之间间隙。

目的：防止幻读。 两种降级场景：

1. 查询条件是**唯一索引等值匹配，命中一条记录** → Next-Key Lock 降级为 Record Lock（只锁记录，没有间隙）
2. 等值查询找不到记录 → 退化成 Gap 间隙锁

面试必背：**RR 级别幻读靠 MVCC + Next-Key Lock（临键锁）共同解决**

## 7. 行锁为什么基于索引？无索引会变成表锁？
**问题：InnoDB 行锁是锁行还是锁索引？为什么没有索引会退化成表锁？****答案** InnoDB 行锁**锁的是索引，不是物理行**。 如果 where 条件字段没有索引，MySQL 要扫描全表，所有记录都会被加行锁，等价于锁住整张表，**效果等同于表锁**。

坑：开发经常踩，where 条件没索引，for update 直接锁表，并发卡死。

## 8. 乐观锁 vs 悲观锁（场景题常问）
**问题：乐观锁和悲观锁区别，各自实现方式，适用场景****答案**

+ **悲观锁**：认为并发冲突一定会发生，操作前上锁。InnoDB S/X 行锁就是悲观锁。 实现：`select ... for update` 缺点：锁竞争，容易阻塞死锁；适合写多读少场景。
+ **乐观锁**：认为冲突概率低，不加锁；提交时校验版本。 实现：版本号 version 字段 / CAS。更新时 `update table set version=version+1 where id=xx and version=old` 失败则重试。 缺点：大量并发写时，大量更新失败，CPU 高；适合读多写少场景。

注意：乐观锁是业务层实现，不是数据库原生锁。

## 9. 什么是死锁？产生 4 个必要条件？MySQL 怎么处理死锁？怎么避免死锁？
**问题：死锁产生条件，InnoDB 如何检测死锁，如何避免？****答案** 死锁：两个事务互相持有对方需要的锁，互相等待，谁都不释放。

死锁 4 必要条件（全部满足才会死锁）

1. 互斥条件：锁资源互斥（X 锁）
2. 请求保持：拿到锁，再请求新锁
3. 不可剥夺：锁不能被强行抢占，只能事务主动释放
4. 循环等待：事务形成环形锁等待链

InnoDB 处理死锁：

1. **死锁检测（wait-for graph）**，主动检测死锁；发现死锁，选择代价更小事务 rollback。
2. 死锁检测有性能开销；也可以开启死锁超时 `innodb_lock_wait_timeout`，超时回滚（默认 50 秒）。

✅ 避免死锁方案：

1. 多个资源更新，**统一顺序访问**（最有效）
2. 事务尽量小，尽快提交，缩短锁持有时间
3. 避免 for update 大范围加锁，保证条件走索引
4. 避免在事务中等待用户输入、外部接口调用
5. 尽量一次性锁定需要的资源

## 10. 锁等待超时和死锁的区别？
**答案**

+ 锁等待超时：事务 A 拿锁，事务 B 一直等不到，超过 innodb_lock_wait_timeout，B 回滚。**没有循环等待**。
+ 死锁：两个事务互相等锁，形成环；数据库检测到，主动回滚其中一个事务。

日志：`deadlock found` 就是死锁；lock wait timeout 只是锁等待。

## 11. RC 和 RR 隔离级别锁机制差异（高频对比题）
**答案**

1. RC：**没有间隙锁、没有临键锁，只有记录锁**，会出现幻读；每次查询生成 Read View。
2. RR：默认 Next-key 临键锁；存在间隙锁；事务启动生成 Read View；解决幻读。
3. RC 锁粒度更小，并发更高；RR 锁范围更大，更容易锁冲突。

## 12. 快照读 vs 当前读（必问，结合 MVCC）
**问题：快照读和当前读区别？哪些 SQL 属于当前读？****答案**

+ **快照读**：普通 select，读取 MVCC 历史快照，不加行锁，并发高。RR 下事务内多次快照读看到同一版本。
+ **当前读**：读取最新已提交数据，**会加锁**。 当前读 SQL： `select ... lock in share mode`（S 锁） `select ... for update`（X 锁） `update / delete / insert`（自动 X 锁）

重点：快照读不能读到未提交数据；当前读会阻塞。

## 13. 表锁、行锁优缺点对比
**答案**

+ 表锁：开销小，加锁快；粒度粗；读写互斥；并发低。MyISAM 使用。
+ 行锁：开销大，加锁慢；粒度细；只锁一行；并发高；容易死锁，InnoDB。

## 14. 场景题：`select * from user where name='test' for update;` name 无索引会发生什么？
**答案** name 没有索引，MySQL 全表扫描，对每一行都加上行 X 锁，**等价锁整张表**。其他事务任何修改都会阻塞，并发直接崩掉。

面试坑题，很容易踩。

## 15. 什么是全局锁？什么时候用？
**答案**`flush tables with read lock;` 全局只读锁，整个库只读，所有 DML 阻塞。 使用场景：**全库逻辑备份**（mysqldump）。

8.0 + 推荐使用 `--single-transaction`，基于 RR 快照备份，不用全局锁，不阻塞写入。

## 16. 什么是 MDL 锁（元数据锁 Meta Data Lock，高频！）
**问题：MDL 元数据锁是什么？什么时候触发？坑点？****答案** MDL：元数据锁，保护表结构。访问表的时候自动加 MDL，事务结束才释放。

+ 读 MDL（共享）：select，可以多个事务共存；
+ 写 MDL（排他）：alter table、drop table，和所有 MDL 互斥。

经典坑： 事务 A 开启，执行 select（加 MDL 读锁，事务不提交）； 事务 B 执行 alter table，申请 MDL 写锁，阻塞； 后续所有 select 都会被阻塞，数据库雪崩。 ✅ 解决方案：DDL 尽量业务低峰执行；长事务一定要避免。

# 面试口述精简总结（项目回答话术）
InnoDB 锁分为表级锁和行锁。表锁包含意向锁、MDL 元数据锁；行锁底层锁索引，分为记录锁、间隙锁、临键锁，仅 RR 隔离级别存在间隙锁，用来解决幻读。 锁分为 S 共享锁、X 排他锁。普通 select 是快照读走 MVCC 不加锁；for update、update 等属于当前读加悲观锁。开发要注意：行锁依赖索引，无索引会退化成表锁；MDL 锁在事务结束释放，长事务会阻塞 DDL 引发雪崩。死锁四个条件，开发时统一资源操作顺序、缩小事务来避免。
