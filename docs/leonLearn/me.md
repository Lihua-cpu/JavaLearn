## 👋 开篇：你好，我是程序员木木 Leon
你好，我是木木 Leon，一名全栈开发者。

平时除了写业务代码，我还有一个长期习惯：写博客、整理技术文档。 很多开发者只注重代码实现，而我更偏爱把实践沉淀成文字。遇到线上问题、技术调研、踩坑复盘，都会记录下来，形成博客文章或者结构化文档。在我看来，输出不是额外负担，而是检验自己是否真正理解一项技术最好的方式。有人说 AI 时代了，写博客已经过时了，在我看来，AI 时代不缺的是知识，缺的是懂知识的人，懂使用 AI 的人。

## 🧩 技术栈与方向
我主要做全栈开发，日常技术领域：

+ 前端：Vue / React 
+ 跨端：Uniapp、React Native
+ 后端：Java，熟悉 Spring 生态、微服务架构
+ 数据库：MySql、Redis
+ 中间件：ES、RabbitMQ、Kafka 等
+ 当前重点实践：RAG、AI Agent、大模型应用开发，探索 AI 赋能业务的落地思路

不只是停留在 API 调用层面，会关注底层原理、工程化落地、分布式场景下的问题。持续学习，持续验证想法。

## 📝 为什么坚持写博客和文档
很多人问我，开发本身就很忙，为什么还要花时间写文章？

1. **给自己留一份知识库**。项目久了，很多解决方案容易遗忘。博客和文档是我的外部记忆，以后遇到同类问题可以快速回看。
2. **倒逼思考，补齐认知漏洞**。写代码可以 “跑通就行”，但写文档需要把逻辑讲清楚。一旦动笔，很多之前忽略的细节、模糊的概念就会暴露出来。
3. **分享，希望帮到同行**。技术路上踩过不少坑，我深知一份清晰的文档、一篇踩坑笔记，能节省大量查阅资料的时间。如果我的文章能帮到正在遇到同类问题的开发者，就是额外收获。

我的文章不会堆砌理论空话，优先写**落地实践、踩坑总结、可复现的方案**。

## 🎯 现阶段目标
持续深耕全栈体系，重点打磨 AI 应用开发能力。 坚持稳定输出博客与技术文档，把零散的项目经验系统化。 在技术上不浅尝辄止，多研究底层，重视架构设计与工程质量。
